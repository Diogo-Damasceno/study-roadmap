Como funciona o banco de dados e a segurança

Texto direto, sem juridiquês. O objetivo é que você confie no que acontece com os seus dados.

O que é o banco

Cada instalação do servidor usa um SQLite — um arquivo único (estudos.db) no próprio servidor. Não há servidor de banco separado, não há nuvem obrigatória. É o mesmo mecanismo usado em milhões de aplicativos (navegadores, celulares).

O que é salvo

  • Sua conta: nome de usuário, (opcional) e-mail vindo do GitHub, e o hash da sua senha.
  • Seu progresso: quais exercícios você marcou como concluídos e quais trilhas favoritou. Só isso.
  • Nada de conteúdo dos exercícios é copiado para o banco — o conteúdo fica nos arquivos de trilhas no servidor e é enviado para você ler.

Como sua senha é protegida

A senha nunca é armazenada em texto puro. Ela passa por bcrypt (custo 12), uma função de hash só de ida: mesmo quem tiver acesso ao arquivo do banco não consegue recuperar a senha original — só verificar se a senha digitada bate com o hash. Login e cadastro também têm limite de tentativas (rate limit) para dificultar força bruta.

Como a sessão funciona

Após autenticar, o servidor cria uma sessão assinada. O cookie da sessão é httpOnly (o JavaScript da página não consegue ler) e sameSite=lax. Em produção o cookie também é secure (só trafega por HTTPS). Nenhuma senha trafega depois do login.

Cabeçalhos e proteções

O servidor aplica Content-Security-Policy, X-Frame-Options e outras proteções via Helmet, impedindo injeção de scripts de terceiros e clickjacking.

O login com GitHub

É um OAuth padrão: você autoriza o GitHub e recebe de volta apenas identificador público e e-mail (se permitido). O segredo do aplicativo fica só no servidor (variáveis de ambiente). Se o operador não configurar as credenciais, o botão simplesmente informa que não está disponível — nada quebra.

Limites honestos

  • Se o servidor for hospedado por terceiros, o operador técnico tem acesso ao banco. Por isso recomendamos hospedar você mesmo (veja o README).
  • Em redes públicas, use sempre HTTPS (proxy reverso com TLS).
  • A execução de código (quando habilitada para laboratório local) é opcional e desligada por padrão em produção.

Seus direitos

Você pode pedir a exclusão da sua conta e de todo o progresso a qualquer momento (basta apagar a linha correspondente no banco, ou solicitar ao administrador). O conteúdo educacional permanece livre para estudar.
